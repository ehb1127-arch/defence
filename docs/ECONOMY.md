# 재화 / 계정 서버 저장

코인·아이템·강화·스테이지 ★·업적·일일 미션 등 **계정 재화는 전용 서버(OCI)가 기준**입니다.

## 구조

```
클라이언트 (Profile.gd)                      전용 서버 (Net.gd)
─────────────────────────                    ─────────────────────────────────────
버튼 → Profile.buy_item("x")                  계정마다 Profile.gd 인스턴스(server_side=true)
  ① 로컬에서 바로 반영 (반응 빠름)
  ② sync("buy_item", ["x"]) ───────────────▶ _s_op: 같은 함수 run_op("buy_item", ["x"]) 실행
                                              server_db.json 에 저장
  ③ apply_server(서버 값) ◀──────────────── _c_op(req_id, 결과, 계정 전체)
     → 로컬 파일을 서버 값으로 덮어씀
```

- **같은 규칙 코드(Profile.gd)를 서버와 클라이언트가 같이 씁니다.** 규칙을 바꾸면 서버도 같은 빌드로 재배포.
  (공지·코인 이벤트는 재배포 없이 `server_config.json` 으로 — docs/OCI_DEPLOY.md)
- 서버가 허용하는 작업은 `Profile.OPS` 목록뿐 (`buy_item`, `buy_perk`, `level_up_unit`, `claim_daily`, `attend`,
  `claim_chest`, `claim_idle`, `use_item`, `take_loadout`, `ad_reward`, `roulette`, `match_end`, `begin_match` …).
- 인자는 클라이언트가 보낸 값이므로 `run_op` 가 종류·범위를 다시 확인합니다 (문자열 32자, 정수만, 없는 id 거절).
- 결과가 난수인 작업(룰렛, 광고 랜덤 아이템)은 `await Profile.request(...)` 로 **서버 결과를 기다립니다**.
- 로컬 파일을 고쳐도 다음 서버 응답에서 서버 값으로 돌아갑니다 (`tests/econ_test.gd` 로 확인).

## 하루 초기화 = 한국 시간 자정

광고 횟수·일일 미션·출석·룰렛·오늘의 결계(`Story.daily_id()`)는 모두 `Profile.today()` 기준입니다.
`today()` 는 **UTC+9 로 계산한 날짜**라 서버(OCI 는 UTC)와 기기의 시간대 설정과 상관없이 같습니다.
접속하면 `_c_welcome` 의 서버 시각으로 `Story.clock_offset` 을 맞춰, 기기 시계를 바꿔도 초기화·방치 보상이 흔들리지 않습니다.

## 판 표와 판 정산

게임 계산은 클라이언트가 하므로 판 결과는 **요약(summary)** 으로 보냅니다 (`Match._match_summary()`).

1. 판이 실제로 시작될 때 `Profile.begin_match(mode, stage)` → 서버가 **판 표**(모드·스테이지·난이도·시작 시각)를 기록.
   지금 온라인 방에서 게임 중이면 서버가 "온라인 판"으로 적습니다 (연승 보너스·난이도 보상 없음).
2. 판이 끝나면 `match_end` 요약. 서버 `Profile.validate_summary()`:
   - 표가 있고 모드·스테이지가 같으면: **걸린 시간으로 갈 수 있는 라운드까지만** 인정
     (`GameData.min_match_time` 의 최소 게임 시간 ÷ 최대 배속 3, 온라인 판은 배속 없음, 여유 15% + 10초.
     예: 40라운드는 3배속으로도 약 4분 반). 표는 **한 번만** 쓰입니다.
   - 서버 연결 전에 시작한 판은 연결되는 대로 표를 요청합니다 (`Profile._begin_unsent`).
   - 온라인 대전을 시작한 계정은 30분 안의 대전 요약을 **그 온라인 판**으로 봅니다 (승패는 서버 레이팅 결과).
     오프라인 대전인 척 진 판을 승리로 정산할 수 없습니다.
   - 표가 없으면 오프라인에서 한 판을 재접속 때 재전송한 것으로 보고 **하루 8번까지만** 인정 (넘으면 `rejected`).
     오프라인 판은 라운드 50 상한, 온라인 판으로 인정하지 않음.
   - 라운드·처치 수·신화/보스/합성 수 상한, 스테이지는 해금된 것만, 승리는 마지막 라운드까지 간 경우만,
     난이도 보상은 표에 적힌 난이도 이하만, 도감은 실제 있는 유닛만
   - 온라인 대전의 승패는 서버가 반영한 레이팅 결과를 따름 (docs/PROTOCOL.md "대전 결과")
3. 판 정산은 계정마다 **최대 12회 몰아서 + 60초마다 1회** (무한 반복 차단).
4. 판 표가 있는 검증된 정산만 랭킹(무한/탑/오늘의 결계)에 기록됩니다.

> 완전한 검증(서버가 게임을 다시 계산)은 아니므로, 이득을 "걸린 시간 안에 받을 수 있는 최대치"로 제한하는 방식입니다.

## 광고 보상 한도 (하루, 한국 시간)

| 광고 | 한도 | 확인 함수 | 넘으면 |
| --- | --- | --- | --- |
| 상점 광고 (코인·랜덤 아이템) | 8 (`GameData.AD_DAILY_LIMIT`) | `ads_left()` | 버튼 막기 |
| 판 결과 코인 2배 | 10 (`Profile.RESULT_AD_DAILY`) | `result_ads_left()` | `apply_match_end()` 결과의 `ad_double` 이 `false` |
| 방치 보상 2배 | 6 (`Profile.IDLE_AD_DAILY`) | `idle_ads_left()` | `claim_idle(2)` 가 1배로 지급 (받은 코인 반환) |
| 룰렛 광고 | 3 (`GameData.ROULETTE_AD_SPINS`) | `roulette_ads_left()` | -1 |

`claim_idle` 배수는 서버에서도 **1~2 로 고정**됩니다 (조작된 배수 무시).

## 코인 이벤트

`server_config.json` 의 `coin_event_mult`(1~5)가 **서버에서** 판 정산 코인에 곱해집니다.
클라이언트도 같은 값을 받아 미리 보기에 씁니다 (`Profile.coin_mult`, 이벤트 이름은 `Net.server_config.event_name`).

## 첫 접속 (계정 이전)

서버에 계정 재화가 없으면 기기 진행을 한 번 올려 받습니다 (`Net.sanitize_migration`).
조작 방지:
- 코인 ≤ 5000, 레벨 ≤ 30, 아이템 ≤ 10개, 연승 ≤ 5, 기록 상한, 도감은 실제 유닛만
- 영구 강화(특성·유닛 레벨)는 **코인 가치 12,000 까지만** 인정 (모든 항목을 1레벨씩 번갈아 올리며)
- 옮긴 기록으로 이미 도달한 업적 단계와 ★ 상자는 "받은 것"으로 처리
- 하루 단위 값(광고 횟수·룰렛·일일 미션)과 판 표는 새로, 결제 상품(광고 제거 등)은 옮기지 않음

## 계정 복구 (새 폰 / 재설치)

계정 키는 기기에서 만든 무작위 `device_id` 입니다. 앱을 지우거나 폰을 바꾸면 **복구 코드**로 되찾습니다.

1. (예전 기기, 서버 연결 중) 설정 → `Net.request_recovery_code()` → `XXXX-XXXX-XXXX` 를 적어 두기
2. (새 기기) 서버 연결 → `Net.redeem_recovery_code(code)` → 성공하면 이 기기가 그 계정이 되고
   진행·재화·결제(광고 제거 등)가 서버 값으로 바뀝니다. 그 계정으로 접속 중인 다른 기기는 연결이 끊깁니다.
3. 코드를 모르고 결제만 복원하려면: 같은 Google 계정이면 스토어의 영수증으로 1회 상품(광고 제거·초보자 꾸러미 기록)이
   새 계정에 **복원**됩니다 (코인·아이템은 다시 주지 않음, 영수증 하나로 최대 3개 계정). docs/IAP.md

출시 후 권장: Google Play 게임즈 로그인(서버 인증 코드 → 서버 확인)을 붙이면 `_s_hello` 의 `device_id` 자리를
검증된 플레이어 ID 로 바꾸는 것만으로 나머지는 그대로 동작합니다.

## 오프라인

- 서버 계정과 연결된 적 있는 기기(`Profile.linked`)는 오프라인에서도 플레이 가능.
  작업은 `pending_ops` 에 쌓였다가 **다음 접속 때 순서대로 서버에 재전송**됩니다 (최대 200개, 판 표는 안 쌓음).
- 서버에 한 번도 접속하지 않은 기기는 순수 로컬 저장 (싱글 전용).
- 메뉴에 들어오면 `Net.server_address` 로 조용히 접속합니다 (설정 > "시작할 때 서버 계정과 동기화").
  서버 주소는 프로젝트 설정 `application/online/server_url` (docs/OCI_DEPLOY.md).

## 기기 저장 (profile.cfg)

- 값이 바뀌면 `changed` 는 바로, 파일 쓰기는 한 프레임에 한 번으로 모아서 (`Profile.flush()`; 앱이 내려갈 때도 씀)
- `profile.cfg.tmp` 에 쓰고 → 이전 파일은 `profile.cfg.bak` 으로 → 임시 파일을 `profile.cfg` 로 (중간에 꺼져도 안전)
- 읽을 때 본 파일이 깨졌으면 `.bak` → `.tmp` 순서로 복구
- 계정 ID 는 `account.cfg` 에 따로 저장: 프로필이 깨져도 서버 계정을 잃지 않음
- 저장 형식 버전 `version` (`Profile.SAVE_VERSION`, 올릴 때 `_migrate_save` 에 변환 추가)

## 저장 파일 (서버)

| 파일 | 내용 |
| --- | --- |
| `server_db.json` | 기기(계정)별 이름·레이팅·전적·랭킹 기록·복구 코드 + `profile`(재화 전체) |
| `server_iap.json` | 결제 영수증 기록 (중복 지급 방지·복원·환불 회수) |

| `backups/` | 한 시간마다 자동 백업 (사흘치) |
